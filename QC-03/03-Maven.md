## 1. What is Maven?

### Simple Explanation

Maven is a **build tool** for Java projects. It does three main things:

1. **Manages dependencies** — Downloads libraries (JARs) you need automatically
2. **Builds your project** — Compiles, tests, and packages your code
3. **Standardizes structure** — Every Maven project looks the same

### Analogy

Think of Maven like a **recipe manager and kitchen assistant** for cooking:
- **Recipe** = POM file (tells what ingredients you need)
- **Ingredients** = Dependencies (libraries like Spring, JUnit)
- **Grocery Store** = Maven Repository (where ingredients are downloaded from)
- **Kitchen Layout** = Standard project structure (everything in its place)
- **Cooking Steps** = Build lifecycle (prep → cook → serve)

Without Maven, you'd manually:
- Download JAR files from websites
- Put them in the correct folders
- Write compile commands yourself
- Hope nothing breaks when sharing code with others

## 2. Why Do We Need Maven?

### The Problem Without Maven

```
Day 1: You need Spring Framework
  → Google "Spring download"
  → Download spring-core-5.3.jar
  → Put it in a /lib folder
  → Add it to classpath manually

Day 2: Spring needs commons-logging
  → Download commons-logging-1.2.jar
  → That needs another dependency...
  → And another...
  
Day 3: Share project with teammate
  → "It works on my machine!" 😢
  → Teammate has different JAR versions
```

### The Solution With Maven

```xml
<!-- Just write this in pom.xml -->
<dependency>
    <groupId>org.springframework</groupId>
    <artifactId>spring-core</artifactId>
    <version>5.3.20</version>
</dependency>
<!-- Maven downloads spring-core AND all its dependencies automatically -->
```

### Key Benefits

| Benefit | Description |
|---------|-------------|
| Dependency Management | Automatically downloads and manages libraries |
| Standard Structure | Every project looks the same |
| Build Automation | One command to compile, test, and package |
| Transitive Dependencies | Downloads dependencies of dependencies |
| Reproducible Builds | Same result on every machine |
| IDE Integration | Works with IntelliJ, Eclipse, VS Code |

## 3. Maven Project Structure

### Standard Directory Layout

```
my-project/
├── pom.xml                          ← Project configuration (THE HEART)
├── src/
│   ├── main/
│   │   ├── java/                    ← Your application source code
│   │   │   └── com/
│   │   │       └── example/
│   │   │           └── App.java
│   │   └── resources/               ← Configuration files, properties
│   │       ├── application.properties
│   │       └── templates/
│   └── test/
│       ├── java/                    ← Your test source code
│       │   └── com/
│       │       └── example/
│       │           └── AppTest.java
│       └── resources/               ← Test-specific resources
│           └── test-data.sql
└── target/                          ← Build output (generated by Maven)
    ├── classes/                     ← Compiled .class files
    ├── test-classes/                ← Compiled test classes
    └── my-project-1.0.jar           ← Final packaged JAR
```

### Why This Structure?

**Convention over Configuration** — Maven expects files in specific places:
- Source code in `src/main/java` → Maven knows to compile it
- Test code in `src/test/java` → Maven knows to run tests
- Resources in `src/main/resources` → Maven copies them to output

You DON'T need to tell Maven where to find things. It already knows!

### Under the Hood: What Maven Does with Each Directory

```
src/main/java/      → Compiles to → target/classes/
src/main/resources/  → Copies to  → target/classes/
src/test/java/       → Compiles to → target/test-classes/
src/test/resources/  → Copies to  → target/test-classes/

Everything in target/classes/ gets packaged into the final JAR/WAR
```

## 4. POM (Project Object Model)

### What is POM?

The `pom.xml` is the **central configuration file** of a Maven project. It defines:
- Project identity (who is this project?)
- Dependencies (what libraries does it need?)
- Build config (how to build it?)
- Plugins (extra tools to use during build)

### Basic POM Structure

```xml
<?xml version="1.0" encoding="UTF-8"?>
<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 
         http://maven.apache.org/xsd/maven-4.0.0.xsd">
    
    <!-- POM model version (always 4.0.0) -->
    <modelVersion>4.0.0</modelVersion>
    
    <!-- ===== PROJECT IDENTITY ===== -->
    <!-- These three together form the unique ID of your project -->
    <groupId>com.example</groupId>         <!-- Organization (like a domain name) -->
    <artifactId>my-app</artifactId>        <!-- Project name -->
    <version>1.0.0</version>               <!-- Version number -->
    <packaging>jar</packaging>             <!-- Output format: jar, war, pom -->
    
    <!-- ===== PROJECT INFO ===== -->
    <name>My Application</name>
    <description>A simple Spring Boot application</description>
    
    <!-- ===== PROPERTIES ===== -->
    <properties>
        <java.version>17</java.version>
        <spring.version>5.3.20</spring.version>
        <maven.compiler.source>17</maven.compiler.source>
        <maven.compiler.target>17</maven.compiler.target>
    </properties>
    
    <!-- ===== DEPENDENCIES ===== -->
    <dependencies>
        <dependency>
            <groupId>org.springframework</groupId>
            <artifactId>spring-core</artifactId>
            <version>${spring.version}</version>    <!-- Uses property -->
        </dependency>
        
        <dependency>
            <groupId>junit</groupId>
            <artifactId>junit</artifactId>
            <version>4.13.2</version>
            <scope>test</scope>         <!-- Only available during testing -->
        </dependency>
    </dependencies>
    
    <!-- ===== BUILD CONFIG ===== -->
    <build>
        <plugins>
            <plugin>
                <groupId>org.apache.maven.plugins</groupId>
                <artifactId>maven-compiler-plugin</artifactId>
                <version>3.10.1</version>
                <configuration>
                    <source>17</source>
                    <target>17</target>
                </configuration>
            </plugin>
        </plugins>
    </build>
</project>
```

### GAV Coordinates (Project Identity)

Every artifact in Maven is identified by **three coordinates** (GAV):

```
groupId    = com.example          (Organization — like a package name)
artifactId = my-app               (Project name)
version    = 1.0.0                (Version)

Combined: com.example:my-app:1.0.0   ← Unique identifier worldwide!
```

### Spring Boot POM (with Parent)

Most Spring Boot projects inherit from a **parent POM**:

```xml
<project>
    <modelVersion>4.0.0</modelVersion>
    
    <!-- Inherit from Spring Boot parent -->
    <parent>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-parent</artifactId>
        <version>3.2.0</version>
    </parent>
    
    <groupId>com.example</groupId>
    <artifactId>my-spring-app</artifactId>
    <version>1.0.0</version>
    
    <dependencies>
        <!-- No version needed! Parent manages versions -->
        <dependency>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-starter-web</artifactId>
        </dependency>
        
        <dependency>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-starter-test</artifactId>
            <scope>test</scope>
        </dependency>
    </dependencies>
</project>
```

**Why Parent POM?** The parent provides:
- Tested, compatible versions for all Spring Boot dependencies
- Default plugin configurations
- Java version settings
- You don't need to specify versions — the parent handles version compatibility

## 5. Dependencies and Dependency Management

### What is a Dependency?

A dependency is an **external library** your project needs. Instead of downloading JARs manually, you declare them in `pom.xml` and Maven downloads them.

### How Dependencies Work

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>   <!-- Who made it -->
    <artifactId>spring-boot-starter-web</artifactId> <!-- What is it -->
    <version>3.2.0</version>                        <!-- Which version -->
    <scope>compile</scope>                           <!-- When to use it -->
</dependency>
```

### Dependency Scopes

Scopes control **when** a dependency is available:

| Scope | Available During | Included in Final JAR | Example |
|-------|-----------------|----------------------|---------|
| `compile` (default) | Compile + Test + Runtime | Yes | Spring, Jackson |
| `provided` | Compile + Test | No (server provides it) | Servlet API, Lombok |
| `runtime` | Test + Runtime | Yes | MySQL driver |
| `test` | Test only | No | JUnit, Mockito |
| `system` | Compile + Test | No (from local path) | Rarely used |

```xml
<!-- Compile scope (default) — available everywhere -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-web</artifactId>
</dependency>

<!-- Test scope — only for testing -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-test</artifactId>
    <scope>test</scope>
</dependency>

<!-- Runtime scope — not needed for compilation, but needed at runtime -->
<dependency>
    <groupId>mysql</groupId>
    <artifactId>mysql-connector-java</artifactId>
    <scope>runtime</scope>
</dependency>

<!-- Provided scope — available for compile, but server provides it at runtime -->
<dependency>
    <groupId>javax.servlet</groupId>
    <artifactId>javax.servlet-api</artifactId>
    <scope>provided</scope>
</dependency>
```

### Transitive Dependencies

When you add a dependency, it may have its **own dependencies**. Maven downloads ALL of them automatically.

```
You add: spring-boot-starter-web
  ├── spring-web
  │   ├── spring-beans
  │   └── spring-core
  ├── spring-webmvc
  │   ├── spring-aop
  │   └── spring-expression
  ├── spring-boot-starter-tomcat
  │   ├── tomcat-embed-core
  │   └── tomcat-embed-websocket
  └── spring-boot-starter-json
      ├── jackson-databind
      └── jackson-core

You wrote 1 dependency → Maven downloaded 15+ JARs automatically!
```

### Excluding Transitive Dependencies

Sometimes you want to exclude a specific transitive dependency:

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-web</artifactId>
    <exclusions>
        <exclusion>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-starter-tomcat</artifactId>
        </exclusion>
    </exclusions>
</dependency>

<!-- Use Jetty instead of Tomcat -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-jetty</artifactId>
</dependency>
```

## 6. Maven Repositories

### What is a Repository?

A repository is a **storage location** where Maven downloads dependencies from.

### Three Types of Repositories

```
┌──────────────────────────────────────────────────────────┐
│                                                          │
│  1. LOCAL Repository (~/.m2/repository)                  │
│     → On YOUR computer                                   │
│     → Maven checks here FIRST                            │
│     → Like a cache                                       │
│                                                          │
│  2. CENTRAL Repository (repo.maven.apache.org)           │
│     → On the internet                                    │
│     → World's largest collection of Java libraries       │
│     → Maven checks here if NOT in local                  │
│                                                          │
│  3. REMOTE Repository (company's private server)         │
│     → Optional, configured in pom.xml                    │
│     → For internal/private libraries                     │
│                                                          │
└──────────────────────────────────────────────────────────┘
```

### How Dependency Resolution Works

```
You declare: spring-core:5.3.20

Step 1: Maven checks LOCAL repo (~/.m2/repository)
        Found? → Use it ✅
        Not found? → Go to Step 2

Step 2: Maven checks CENTRAL repo (internet)
        Found? → Download to local repo, then use it ✅
        Not found? → Go to Step 3

Step 3: Maven checks REMOTE repos (if configured)
        Found? → Download to local repo, then use it ✅
        Not found? → BUILD FAILS ❌
```

### Local Repository Structure

```
~/.m2/repository/
├── org/
│   └── springframework/
│       └── spring-core/
│           └── 5.3.20/
│               ├── spring-core-5.3.20.jar        ← The actual library
│               ├── spring-core-5.3.20.pom         ← Its POM (with its dependencies)
│               └── spring-core-5.3.20.jar.sha1    ← Checksum for integrity
```

## 7. Build Lifecycle

### What is the Build Lifecycle?

The build lifecycle is a **sequence of phases** that Maven executes to build your project. Each phase does a specific task, and they run in order.

### The Default Lifecycle

```
Phase 1: validate     → Check project is correct (POM is valid)
    ↓
Phase 2: compile      → Compile source code (.java → .class)
    ↓
Phase 3: test         → Run unit tests
    ↓
Phase 4: package      → Package compiled code (create JAR/WAR)
    ↓
Phase 5: verify       → Run integration tests and checks
    ↓
Phase 6: install      → Install JAR to local repository (~/.m2)
    ↓
Phase 7: deploy        → Upload JAR to remote repository
```

### Key Rule: Phases Run in Order

When you execute a phase, **all previous phases run first**:

```bash
# Running "package" will execute:
# validate → compile → test → package
mvn package

# Running "install" will execute:
# validate → compile → test → package → verify → install
mvn install

# Running "test" will execute:
# validate → compile → test
mvn test
```

### Other Lifecycles

```
Clean Lifecycle:          Site Lifecycle:
  pre-clean                 pre-site
  clean                     site
  post-clean                post-site
                            site-deploy

mvn clean          → Deletes the "target" directory
mvn clean package  → Clean first, then build (MOST COMMON)
```

### Visual Flow

```
mvn clean package
│
├── CLEAN LIFECYCLE
│   └── clean: Delete target/ directory ♻️
│
└── DEFAULT LIFECYCLE
    ├── validate: Check POM ✓
    ├── compile: javac src/main/java → target/classes ⚙️
    ├── test: Run JUnit tests 🧪
    └── package: Create JAR in target/ 📦

Result: target/my-app-1.0.0.jar
```

## 8. Plugins

### What are Plugins?

Plugins are **tools that do the actual work** in each build phase. Every phase is executed by a plugin. Maven is basically a framework that runs plugins.

### Under the Hood: Phases → Plugins

```
Phase        →  Plugin (that does the work)
────────────────────────────────────────────
compile      →  maven-compiler-plugin      (compiles Java code)
test         →  maven-surefire-plugin      (runs unit tests)
package      →  maven-jar-plugin           (creates JAR file)
install      →  maven-install-plugin       (copies to ~/.m2)
deploy       →  maven-deploy-plugin        (uploads to remote repo)
clean        →  maven-clean-plugin         (deletes target/)
```

### Configuring Plugins

```xml
<build>
    <plugins>
        <!-- Compiler Plugin: Set Java version -->
        <plugin>
            <groupId>org.apache.maven.plugins</groupId>
            <artifactId>maven-compiler-plugin</artifactId>
            <version>3.10.1</version>
            <configuration>
                <source>17</source>     <!-- Java source version -->
                <target>17</target>     <!-- Java bytecode version -->
            </configuration>
        </plugin>
        
        <!-- Surefire Plugin: Configure test execution -->
        <plugin>
            <groupId>org.apache.maven.plugins</groupId>
            <artifactId>maven-surefire-plugin</artifactId>
            <version>3.0.0</version>
            <configuration>
                <includes>
                    <include>**/*Test.java</include>
                    <include>**/*Tests.java</include>
                </includes>
            </configuration>
        </plugin>
        
        <!-- Spring Boot Plugin: Build executable JAR -->
        <plugin>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-maven-plugin</artifactId>
        </plugin>
    </plugins>
</build>
```

### Common Plugins

| Plugin | Purpose |
|--------|---------|
| `maven-compiler-plugin` | Compiles Java code |
| `maven-surefire-plugin` | Runs unit tests |
| `maven-failsafe-plugin` | Runs integration tests |
| `maven-jar-plugin` | Creates JAR files |
| `maven-war-plugin` | Creates WAR files (web apps) |
| `spring-boot-maven-plugin` | Creates executable Spring Boot JARs |
| `maven-dependency-plugin` | Analyze/copy dependencies |
| `jacoco-maven-plugin` | Code coverage reports |

## 9. Running Maven Builds

### Common Maven Commands

```bash
# Clean the project (delete target/ directory)
mvn clean

# Compile source code
mvn compile

# Run tests
mvn test

# Package the project (create JAR/WAR)
mvn package

# Clean and package (MOST COMMONLY USED)
mvn clean package

# Install to local repository
mvn clean install

# Skip tests during build
mvn clean package -DskipTests

# Run a specific test class
mvn test -Dtest=UserServiceTest

# Run Spring Boot application
mvn spring-boot:run

# Display dependency tree
mvn dependency:tree

# Check for dependency updates
mvn versions:display-dependency-updates

# Generate project from archetype (template)
mvn archetype:generate -DgroupId=com.example -DartifactId=my-app
```

### Maven Wrapper (mvnw)

The Maven Wrapper ensures everyone on the team uses the **same Maven version** without installing it globally.

```bash
# On Linux/Mac
./mvnw clean package

# On Windows
mvnw.cmd clean package

# Files created by wrapper:
my-project/
├── mvnw              ← Linux/Mac script
├── mvnw.cmd          ← Windows script
└── .mvn/
    └── wrapper/
        └── maven-wrapper.properties  ← Maven version config
```

### Practical Example: Complete Build Flow

```bash
# Step 1: Create a new Spring Boot project
# Go to https://start.spring.io or use:
mvn archetype:generate \
  -DgroupId=com.example \
  -DartifactId=my-spring-app \
  -DarchetypeArtifactId=maven-archetype-quickstart

# Step 2: Navigate to project
cd my-spring-app

# Step 3: Compile and run tests
mvn clean test
# Output:
# [INFO] --- maven-compiler-plugin:3.10.1:compile ---
# [INFO] Compiling 5 source files to target/classes
# [INFO] --- maven-surefire-plugin:3.0.0:test ---
# [INFO] Tests run: 10, Failures: 0, Errors: 0, Skipped: 0
# [INFO] BUILD SUCCESS

# Step 4: Package as JAR
mvn clean package
# Output:
# [INFO] Building jar: target/my-spring-app-1.0.0.jar
# [INFO] BUILD SUCCESS

# Step 5: Run the application
java -jar target/my-spring-app-1.0.0.jar
# OR
mvn spring-boot:run
```

## Quick Revision Cheat Sheet

```
Maven = Build tool for Java (manages dependencies + builds project)

Project Structure:
  src/main/java      → Source code
  src/main/resources  → Config files
  src/test/java       → Test code
  pom.xml             → Project config
  target/             → Build output

POM (pom.xml):
  GAV = groupId + artifactId + version (unique project ID)
  <dependencies> = libraries you need
  <build><plugins> = tools for building

Dependency Scopes:
  compile (default) → Available everywhere
  test → Test only (JUnit, Mockito)
  runtime → Not for compilation, but needed at runtime (DB drivers)
  provided → Server provides it (Servlet API)

Build Lifecycle (runs in order):
  validate → compile → test → package → verify → install → deploy
  
  mvn package = runs validate + compile + test + package
  mvn clean package = delete target/ THEN build (MOST USED)

Common Commands:
  mvn clean package        → Build the project
  mvn clean package -DskipTests  → Build without tests
  mvn spring-boot:run      → Run Spring Boot app
  mvn dependency:tree      → Show dependency tree

Plugins = Do the actual work in each phase
  compiler-plugin → compiles code
  surefire-plugin → runs tests
  jar-plugin → creates JAR
```
